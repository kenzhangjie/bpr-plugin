02 · 核心论点

Notion 不是给工作加 AI，而是让 AI 来重排流程

替换人 ≠ 替换流程

Sarah 的原话："It's not replacing people, it's replacing processes."
Custom Agent 不是裁员工具，而是把「Slack 里的 bug 报告」「邮件里的租客申请」「合同的起草」这些 流程直接装进 Notion——人还在，但处理路径变了。

WRAPPER 幻觉
"Notion 不就是个 ChatGPT 包装？"
这是 Sarah 拿来反复给候选人解释的问题。她的 Chrome 自动补全里就有这段拒答。 真相是：包装层只是表皮，不产生收入，也不是用户真正需要的。
系统级定位
Datadog 对 AWS，就是 Notion 对 LLM
Datadog 建在云存储之上，但它是"可观测性专家"。
Notion 建在模型之上，但它是"协作与知识的 system of record"——
模型在换，协作的专业度不换。

04 · 产品决策

Flippy：把"设置 Agent"改成"和 Agent 聊天"

Custom Agents 原本的主视图是设置面板，你去配置它要做什么。团队在 alpha 后把整个范式翻过来了——主视图是聊天，Agent 本身能通过对话自己改自己的设置。内部代号叫 Flippy，因为「Flip」了主次关系。

⚙️ Settings 为主
用户先填表单，
再去聊一条对话测试它
→
💬 Chat 为主
"Everything is the agent"——
编辑它、使用它是同一个对话框

发布因此推迟了约一个月。"Painful for a second, then everyone was super bullish." 跨 3 个团队的 3 个工程师临时重组成专项小组推完。

05 · 技术选择

MCP、CLI、模型三角：为什么都要

🔌
MCP
"The dumb simple thing that works"
强权限模型（只能调工具）、lightweight、窄场景最好用。Notion 把自己的 MCP 当 first-class 资产——只要外部还在用，我就一定支持。
⌨️
CLI
为「代码 agent」准备
能力更强，但权限/令牌泄漏风险真实存在。"能直接写代码调 API 的话，我永远不会再用 MCP"。两条路并行，不是二选一。
🗄️
SQLite 集群
Notion 数据库底层
"几百万个小数据库、少数巨型数据库，还要全部很快"。Agent 提交 SQL 时，跑在同一个为人设计的引擎上——没有 agent 专用数据库。
📐
模型三角
Intelligence / Price / Latency
Labs 只比"谁最便宜、谁最强"，中间价位没人填。Notion 接 MiniMax、和开源实验室合作，自己做 optionality 以填这个三角。
💰
定价的第二层含义
Value alignment with capability
Custom Agents 采用 usage-based 定价。一条原则：确定性任务就该走代码，不该烧 token。 同样的工作用 LLM 反复 MCP，"如果还跳出缓存窗口，就要一遍遍重付"——既对用户不划算，也不是好生意。
06 · 新职位

「Notion's Last Exam」的三个全职岗

DATA SCIENTIST
数据科学家
1 人 · 全职负责 eval 集设计
定义什么是"Notion 最后的考试"——像 Humanity's Last Exam 一样的基准，专门用来把现有 eval 饱和后的"没信号"阶段拉回到有判别力。
MBE
Model Behavior Engineer
前身叫 "Data Specialist"
背景多样——Stanford 比较文学新毕业、语言学博士辍学。 原本只是给 Simon 看 Google Sheets 里的模型输出"这条好 / 这条坏"，后来长成了独立职能。Notion 正在招更多 MBE。
EVALS ENG
Evals 工程师
做支撑"30% 通过率"的基础设施
基线要刻意故意做不过，否则给 Anthropic / OpenAI 的反馈就只剩"没变差"。 Notion 过去 2–3 个月和两家实验室一起共建了这类"前沿 / 余量 eval"。

💡 "不是 eval = quality，那就像说 testing = unit test；eval 本身就是一整套质量工程。"

07 · 组织的一面

当模型足够强，组织反而要更松

🎯
杠杆归好奇心
"AI 时代的杠杆会更多地流向最好奇、最兴奋的人。"Image generation 就是一个做数据库的工程师 Jimmy 周末自驱搞起来的——Gemini 额度、token 追踪、email 支持，全量资源让他跑完。
🧱
不是 quarterly hackathon，是日常
创新不是一年 4 次集中冲刺。每天的主业就是建设新东西，不然就死了。领导者必须能放下"我说了算"的自我。
🫙
工具归工具团队
Editor 团队做的 CRDT 现在解决"两个 agent 同时改同一个 block"；SQL 引擎团队负责让 agent 的查询跑得快——没有单独的"agent infra"团队。
⏳
慢一点，再慢一点
"We ship things slowly." Custom Agents 在 alpha 阶段跑了很久：一批人把它做到可上线，另一批人已经在做下一代。延期一个月做 Flippy 值得。
08 · 金句

三句建议钉墙上

"It's not replacing people, it's replacing processes."
—— 它不是在替换人，它是在替换流程。（Sarah 谈 Custom Agent 的真实价值）
"You gradually strip away everything and it looks more AGI-like."
—— 你一层层剥掉脚手架，它就越来越像 AGI。（Simon 谈从 few-shot 到 tools-only 的演化）
"Over time the majority of our traffic will be coming from agents."
—— 长期来看，我们的大部分流量将来自 agent。（这是 Notion 每个产品团队的底层假设）
09 · 给不同人的启示

你该做什么？

做 Agent 产品的
  • Eval 不是一张报表，是三层工程：CI / Launch / Frontier
  • 故意让前沿 eval 只过 30%，否则 signal 饱和
  • 工具海 > 100 个时，上 progressive disclosure
  • 把"编辑 agent"和"使用 agent"合并到同一个对话框
做 Infra / CTO 的
  • MCP 和 CLI 都要支持，别二选一
  • 定价和能力对齐——确定性工作走代码，别烧 token
  • 不要为 agent 做"第二数据库"，复用人用的引擎
  • 招 MBE——跨学科背景比科班更关键
想判断行业趋势的
  • Labs 会继续在最便宜 / 最强两极拉扯，中间留给开源
  • "Agent 流量 > 人类流量"是可下注的假设
  • 系统级能力（协作 / CRDT / SQL）会比模型更值钱
  • "每一项手工流程都值得问：能不能变成 agent？"
