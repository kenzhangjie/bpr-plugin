# 翻译四步法 · Analyze → Translate → Review → Polish

> 📌 **本文件是 BPR 内部副本,服务于 /bpr 流水线**。
> 如果你**不在** /bpr 流程中,而是想单独翻译一段英文 → 用独立的 [`translate` skill](/Users/ken/.claude/skills/translate/SKILL.md)(自动触发,触发词:翻译这段 / 帮我翻 / translate this 等)。
> 两边方法论保持同步(都是四步法)。改一边请同步另一边。

## 为什么用四步法(2026-07 从三步升级)

一次性翻译的瓶颈不是模型"不会",是**没有被引导去自查**:长句容易漏、风格容易飘、翻译腔容易留下、术语容易前后不一致。

在 Andrew Ng 三步法(Translate→Reflect→Improve)上做两处升级:
- ① 前置 **Analyze**:先理解再翻、**定术语表 + 作者语气**,保全篇一致(尤其 BPR 是多章分派翻译,术语不统一是最常见的翻车点)。
- ② 把 Reflect 拆成 **Review(只校准确)+ Polish(只修风格)**:准确性和流畅性**分开优化,不互相妥协**(改流畅时不会悄悄引入误译)。对应信达雅:**Review = 信 / 达,Polish = 达 / 雅**。

## 🤖 给 Claude 的执行指令(/bpr 触发时按这个走)

**BPR 默认分工 = 每篇一次 Analyze(全局)+ 每章两轮子代理(Translate 一轮 → 独立 Review+Polish 一轮)。**
仍然守抗压缩铁律:**英文由你 verbatim 持有,子代理只产出中文**——两轮都只回中文,英文原文永远在你手里。

### Step 0 · Analyze 译前分析(**每篇一次**,在分派翻译之前)

在切章 / 派翻译之前,先定两样东西,写进一个 brief,分派时**塞进每一个子代理的 prompt**(保证跨章一致):
- **术语表(glossary)** ⭐ —— 关键术语统一定调:哪些保留英文、哪些用什么固定中文(如 agency 全篇统一,不许一会儿"能动性"一会儿"agency")。BPR 里可让 structure agent 顺带产出这张表。
- **作者 / 嘉宾语气**(查下方"作者语气速查表";访谈则分别标注 host / guest 语气)。
- **陷阱清单**:习语 / 比喻 / 梗、一词多义、长难句、数字单位。

> 单句 / 短文本可一瞬带过;BPR 整篇**必须显式产出术语表**再开译。

### Step 1 · Translate 直译(子代理第 1 轮)

派翻译子代理,**只给预切好的逐字英文 + 术语表**,一句一句翻,先求"意思对、不漏"。**允许翻译腔**,这一轮不润色。子代理**只产出「中文译文 + 说话人」**,zh 句数必须 == 英文句数。

保留:
- 专有名词、产品名、人名、品牌、公司名(原文不译)
- 已建立的英文术语:PM / IC / PMF / CAC / LTV / ARR / agent / harness / agentic / RAG / leverage / specific knowledge / agency / playbook / flow / token / ROI 等
- 数字、单位、$ 符号(不换算)
- inline link `<a href="...">...</a>`(原样保留;中文段重复同一个 link)

### Step 2 · Review 校准确 + Step 3 · Polish 润色(子代理第 2 轮,**独立 context**)

派**第二个子代理**(全新 context,不是同一个继续聊——这样它看第 1 轮草稿时**不被自己锚定,挑得更狠**),给它:**逐字英文 + 第 1 轮中文草稿 + 术语表 + 语气 brief**。让它**先 Review 再 Polish**,只回最终中文(zh 句数仍 == 英文句数):

**先 Review(只对原文负责,先不管顺不顺)** —— 把准确性问题挑干净:
1. **Accuracy 准确性** — 漏译(整句 / 子句 / 修饰语)/ 加译 / 误译 / 数字 / 单位 / 时间错位
2. **Terminology 术语** — 是否用了术语表、同一概念前后是否一致、保留英文是否真有必要

**再 Polish(只对中文负责)** —— 拿校准后的译文只优化中文:
1. **Fluency 流畅性** — 去翻译腔(对照下方反例表),死盯两类高频失误:
   - **英语习语字面照搬 = 翻车**:先在中文找对应成语,不要逐字翻
     - "world of difference" → ❌"天和地的差别" → ✅**天壤之别**
     - "night and day" → ❌"黑夜和白天" → ✅**天差地别**
     - "moving the needle" → ❌"移动指针" → ✅**撬动结果**
     - "low-hanging fruit" → ❌"挂得低的果子" → ✅**唾手可得的**
     - "boil the ocean" → ❌"把海煮沸" → ✅**想一口吃成胖子**
     - "skin in the game" → ❌"皮肤在游戏里" → ✅**真金白银下场**
   - **行业术语降级到口语 = 翻车**:monetization→**商业化**(不是"收钱")· engagement→**参与度** · retention→**留存** · churn→**流失** · traction→**增长势头** · moat→**护城河** · flow state→**心流** · incrementality→**增量** · ad-hoc purchase→**按需购买**
2. **Style 风格** — 匹配作者 / 嘉宾语气(见速查表)

约束:句级对照不变(一句英→一句中,不合并不拆分)· 中文读着像中文 · 术语/link/专名原则延续 · **Polish 只改"怎么说",不改"说了什么"**(忠实度由 Review 守,别为雅偏离原文)。

> **成本**:每章 2 轮子代理 ≈ 单轮的 2 倍 token / 延迟。这是 BPR 翻译的**默认**(Ken 2026-07 拍板"以后都四步")。整篇太大想省时,可只对**关键章 + TL;DR 金句**升到"极致版四轮独立调用"(见下),其余章仍走这套 2 轮。

最终输出:BPR 标准 `<div class="bilingual">` + `<p class="en">`(你 verbatim 拼回)+ `<p class="zh">`(子代理终稿)。

## 🔥 极致版:四轮独立调用(只对短而高密度的内容)

最高质量做法(四步各一次独立调用):
1. **Analyze** — 通读,产出翻译 brief + 术语表
2. **Translate** — 给 brief + 原文,只产直译草稿
3. **Review** — 给原文 + 草稿 + 术语表,只产"准确性 / 术语"问题列表(新 context,挑得最狠)
4. **Polish** — 给草稿 + Review 问题 + 语气 brief,产润色终稿

代价:4 倍 token / 延迟。**适用**:TL;DR 金句、hero lede、章节标题、招牌句、文化梗、双关——短而高密度。**不适用**:整篇 8000+ 字 podcast 全文(浪费,边际收益低)——全文走上面的"2 轮"默认即可。

## 作者语气速查表

| 作者 | 关键词 | 译文应避免 |
|---|---|---|
| **Naval Ravikant** | 直接 / 反共识 / 口语 / 偶尔挑衅 | 学术腔、长定语、过度修饰 |
| **Paul Graham** | 安静 / 精确 / 不修饰 / 短句多 | 感叹号、强调副词、口语化插入语 |
| **Andrej Karpathy** | 工程师式幽默 / 实用主义 / 自嘲 | 过度严肃、装权威、华丽辞藻 |
| **Lenny Rachitsky** | 友好访谈式 / 提问驱动 | 学究气、机械结构 |
| **Anthropic / DeepMind 官方博客** | 干 / 密 / 谨慎 / 不夸张 | 营销腔、感叹号、夸张副词 |
| **Schopenhauer / Emerson 类经典** | 庄重但有刀锋 / 长句但不拖沓 | 网络口语、emoji 化表达 |

## 反例对照表 · 翻译腔常见结构

| ❌ 翻译腔 | ✅ 自然中文 |
|---|---|
| "他被认为是一个伟大的工程师" | "大家都觉得他是个厉害的工程师" |
| "这是非常重要的事情" | "这件事很重要" |
| "对于初创公司来说,X 是必要的" | "初创公司需要 X" / "做初创离不开 X" |
| "在大多数情况下" | "多数时候" / "一般来说" |
| "这种类型的产品" | "这类产品" / 直接说产品名 |
| "我们应该考虑这个事实,即 X" | "我们应该想想:X" / "别忘了 X" |
| "X,它是 Y" | "X 是 Y" |
| "通过这种方式" | "这样" / "这么做" |
| "在...的过程中" | "...的时候" / "...时" |
| "拥有一个 X" | "有一个 X" / 直接说"有 X" |

## 自检快速 checklist

翻完一段扫一眼:
- [ ] 一句英文 = 一句中文(没合并、没拆分)
- [ ] inline link 在两段都在
- [ ] 同一术语前后翻法一致(对照 Step 0 术语表)
- [ ] 全段没有超过 3 个连续"的"字定语
- [ ] 没有"被...所..."句式(除非真的需要被动)
- [ ] 没有"X 这种东西"的填充表达
- [ ] 数字 / 单位 / 链接全对
- [ ] 大声读一遍中文,像中文,不像翻译软件输出

## 翻译补充约束

> 核心方法论见上文"翻译四步法"。**每章每段都要跑**,不跳过。

补充约束:
- 数字/单位/公司名:保留原文,不汇率换算
- 引用他人:人名英文 + 中文翻译并存
- Sponsor / Outro 段:翻译保留,但 TL;DR 不体现
- 长复合句:可适度拆短,但不省略信息

## 硬约束(不可违反)
### 硬约束 1 · 翻译四步
英文源正文翻译必须走完整四步 Analyze → Translate → Review → Polish,一步不省(每篇先 Analyze 定术语表;每章 Translate → 独立 Review → 独立 Polish)。

### 硬约束 2 · 逐字全覆盖 + 中文去口语词
- 英文行:逐字逐句保留原话(含口语水词),句级全覆盖不压缩(覆盖率硬闸:渲染句数 ÷ 源稿 < ~85% 判不合格,回 TRANSLATE 补)。
- 中文行:Polish 步删掉无意义口语水词(呃/嗯/you know/I mean/the thing is 之类),让中文读起来干净、书面化。
- 边界:只去无意义水词,不去有语义的迟疑/强调(刻意停顿、honestly 这类带态度的词)。
- ⚠️ 这推翻旧规则"口语感保留 uh/um→呃/嗯":新规则 = EN 逐字保留(可学口语)+ ZH 润色去水词(好读),不对称处理。这是本次唯一有意的行为改动。
- 例外:TL;DR·速读 和 Contrarian Takes 两块本就是浓缩,不受逐字约束。
